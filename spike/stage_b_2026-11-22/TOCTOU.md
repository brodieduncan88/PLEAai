# T15: time-of-check/time-of-use review (fclib.py, prereq.py, recover.py)

Written before any run. Threat model: the guest payload is untrusted, and so is the guest kernel once
the payload runs. The jailed VMM is treated as possibly compromised after boot. Root on the host is
trusted, so a race that only root can win is listed as **residual**. Nothing below was exercised
against KVM by the author. T15 demonstrates only item 2.

| # | Check (time of check) | Use (time of use) | Window and who can race it | Mitigation in this bundle | Residual |
|---|---|---|---|---|---|
| 1 | `prereq` P06 hashes `/opt/plea-fc/bin/{jailer,firecracker}` and checks root ownership and mode on every path component | `subprocess.Popen(jailer)`. The jailer then copies `firecracker` into the chroot and execs it | From the hash to the exec, and from the jailer's copy to its exec. Only root can write those paths | Path components are root-owned and not group/other-writable (P06). At READY, fclib hashes `/proc/<pid>/exe`, which is the inode actually executing, and `ok` requires it to equal the pin (T02.P7) | This is detection after exec, not prevention. A root-level swap of the jailer itself is not detected |
| 2 | `prereq` P07/P08 hash the kernel and rootfs sources (full hash in the test gate; size only per launch) | Firecracker opens `/vmlinux` and `/rootfs.ext4` in the chroot | From the source check to the copy (root only) | `place_file` copies to a new file (`O_EXCL\|O_NOFOLLOW`), then re-reads the copy and compares it with the pin. That comparison is the binding check. A changed source is refused (T15 demo, selftest) | From the post-copy hash to Firecracker's open. The copy sits in a root-created 0755 directory under a root-owned base, so only root can change it |
| 3 | Pins file read by `prereq` | Pins re-read by `run_vm` for the post-copy comparison | Between the two reads (root only) | P05 checks that `pins.json` and its path are root-owned and not group/other-writable | A root edit between the reads goes unnoticed |
| 4 | `lease_uid` sees no process and no passwd entry for a uid, then creates `leases/<uid>` with `O_EXCL` | The jailer drops to that uid/gid | Between the scan and the exec. Only root can start processes under an arbitrary uid. Leases serialise our own allocations | T02.P1 checks that every uid/gid field at READY equals the allocated id. Cleanup and recover kill every process with that uid | A foreign root process using the 64000–64999 range would collide (and be killed). The range is assumed dedicated |
| 5 | `prereq` P04 checks that the parent cgroup has cpu/memory/pids in `subtree_control` and no member processes | The jailer creates `<parent>/<id>` and writes the limits | Until the VMM runs (root only) | The limits are read back at READY (`cgroup_at_ready`) and compared with the declared values (T02.P5). `/proc/<pid>/cgroup` is compared with the expected path (T01.P3, T02.P4) | none beyond root |
| 6 | Cleanup sees `cgroup.procs` empty | `rmdir` of the cgroup | A process could join in between (root only) | The kernel refuses `rmdir` (EBUSY) on a non-empty cgroup, so the race fails safe and is reported as leftover | none |
| 7 | Chroot id dir created with `os.mkdir` (fails if it exists). The exec dir's `path_problems` are checked after `makedirs` | Files are placed in the chroot and the jailer chroots into it | The base is root-owned (P09) | Fresh id per launch. `O_EXCL\|O_NOFOLLOW` for every file we create, so a pre-planted symlink fails | none beyond root |
| 8 | `mounts_under(chroot)` is empty and `realpath` is inside the base | `safe_rmtree` | Between the check and the removal (root only) | `shutil.rmtree` is fd-based (`avoids_symlink_attacks` is required). `safe_rmtree` refuses symlinked or outside paths. The jailer's mounts live in its private mount namespace | none beyond root |
| 9 | The VMM has exited (`proc.wait`) | The host reads `out.img`, which is owned by the VM uid | Any surviving process with that uid could rewrite the image during the read | Before reading, every process with the VM uid is SIGKILLed and the result is not read if any survive. The content is validated as untrusted (`read_result`/`parse_result` caps and lengths) | none |
| 10 | Host computes the payload sha256 and writes `in.img` (root:gid 0440, `O_EXCL`) | The guest extracts the payload to tmpfs, hashes it, compares with `plea.sha256` and runs it as uid 10001 | The extracted file is root-owned 0444 in a root 0755 dir, so the workload cannot modify it between hash and exec | The guest hash check (T09.P1/P2). The input drive is read-only and its host hash is unchanged after the run (`in_img_unchanged`, T09.P5) | A compromised guest kernel could lie in its header. The host treats every header field as untrusted data |
| 11 | `recover.py` scan | Kill, rmdir and rmtree on the scanned objects | A launch could start between scan and action | `--apply` takes the run lock exclusively and non-blocking **before** rescanning. Every launch holds it shared, so recover refuses while any VM is active | Processes outside the uid range are reported, never killed |
| 12 | `run_stage.sh` verifies `declared/SHA256SUMS` | Python and shell files are read later, during the stage | Edits during the run | P13 requires the bundle path to be root-owned and not group/other-writable. `python3 -I -B` with `sys.path.append` keeps the stdlib first and writes no `.pyc` | Only root can edit during the run |
| 13 | `flag_check` parses `--help`/`--version` once per process | Later launches build the argv | Binary replaced after the check | Covered by item 1 (path ownership, exe hash at READY) | as item 1 |
| 14 | Stage 1 TOFU hashes of the kernel/squashfs | Every later stage | Upstream content can change between first download and later | Pins are written on first download. A later download that differs is NOT MET. No published checksum or signature exists, so TOFU proves only that the content is consistent with the first download | The authenticity of the CI artifacts is unverified |
| 15 | `/dev/kvm` checked on the host (P01/P02) | The jailer mknods its own `/dev/kvm` (10:232) inside the chroot | — | The VMM never uses the host path, so a host-node swap does not reach the VM | none |
